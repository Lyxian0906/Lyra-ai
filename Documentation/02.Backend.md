# The Backend, Piece by Piece

## `app.py`

### Setup
```python
load_dotenv()
api_key = os.getenv("GEMINI_API_KEY")
client = genai.Client(api_key=api_key)
```
Loads your `.env` file, pulls out `GEMINI_API_KEY`, and creates one Gemini
client for the whole app to reuse. This runs once, when the server starts —
not on every message.

### The routes

`app.py` defines everything the browser is allowed to ask for:

- **`GET /`** → returns `index.html`. This is what loads when you visit
  `http://127.0.0.1:5000`.
- **`GET /Script/<file>`** and **`GET /Styles/<file>`** → serve your JS/CSS
  files. Flask normally only serves a folder named `static/`; since this
  project uses `Script/` and `Styles/` instead, these two routes exist to
  serve those folders manually.
- **`POST /chat`** → the important one. Takes `{ message: "..." }`, talks to
  Gemini, returns `{ response: "..." }`.
- **`POST /reset`** → wipes `conversation.json` so the next message starts a
  fresh conversation.

### Memory: `load_history()` / `save_history()`

```python
def load_history():
    if os.path.exists(HISTORY_FILE):
        with open(HISTORY_FILE, "r") as f:
            return json.load(f)
    return []
```
Reads the JSON file into a Python list. If the file doesn't exist yet
(first run), it just returns an empty list instead of crashing.

```python
contents = [
    {"role": turn["role"], "parts": [{"text": turn["text"]}]}
    for turn in history
]
```
Gemini doesn't accept your `{"role": ..., "text": ...}` shape directly — it
wants `{"role": ..., "parts": [{"text": ...}]}`. This line converts your
simple storage format into what the API expects. Keeping your *storage*
format simple and only converting it right before the API call means you're
not locked into Gemini's specific shape if you ever swap providers.

### The actual Gemini call

```python
response = client.models.generate_content(
    model="gemini-3.6-flash",
    contents=contents,
    config=types.GenerateContentConfig(
        system_instruction=SYSTEM_PROMPT,
        tools=LYRA_TOOLS
    )
)
```
This is the one line doing all the work. `contents` is the memory,
`system_instruction` is the personality, `tools` is what she's allowed to do.
If a tool is needed, the SDK handles calling it and re-prompting Gemini
automatically — you never see that intermediate step, you just get the
final `response.text`.

### Error handling
```python
except Exception as e:
    print("Gemini error:", e)
    return jsonify({"response": "Lyra hit an error..."}), 500
```
If the API call fails (bad key, network issue, rate limit), the server
doesn't crash — it logs the real error to your terminal (for you to debug)
and sends a friendly message to the browser (for the user to see).

## `persona.py`

Just one variable: `SYSTEM_PROMPT`, a string. This is the *only* file you
should need to edit to change how Lyra talks, what she knows about you, or
what rules she follows. Everything else in the app is plumbing; this is the
content.

## `tools.py`

Each tool is a plain Python function:

```python
def get_current_time() -> str:
    """Returns the current local date and time. Use this whenever the user
    asks what time or day it is, or anything relative to 'now'."""
    return datetime.now().strftime("%A, %B %d, %Y at %I:%M %p")
```

Two things matter here, and Gemini reads both:
- **The docstring** — tells the model *when* to use this tool
- **The type hints** (`-> str`, or `location: str`) — tells the model what
  shape of data to pass in and expect back

You never call these functions yourself. You just define them, list them in
`LYRA_TOOLS` in `app.py`, and Gemini decides at runtime whether a given
message needs one.
