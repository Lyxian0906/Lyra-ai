# How Lyx AI Works — The Big Picture

Before diving into individual files, it helps to see the whole request end to end.

## The flow of one message

```
 You type "hey lyra"
        │
        ▼
 [Script/script.js]  sendMessage()
        │  fetch POST /chat  { message: "hey lyra" }
        ▼
 [app.py]  Flask route /chat
        │
        ├─ 1. Load conversation.json (past messages)
        ├─ 2. Append your new message to it
        ├─ 3. Send the WHOLE history + persona.py's SYSTEM_PROMPT
        │      + tools.py's functions to Gemini
        ▼
 [Google Gemini API]
        │  model reads the system prompt, the history, decides:
        │  "do I need a tool, or can I just answer?"
        │
        ├─ if a tool is needed → SDK calls the Python function in
        │   tools.py automatically → sends result back to Gemini →
        │   Gemini writes the final reply using that result
        │
        ▼
 [app.py]  gets response.text back
        │
        ├─ 4. Append Lyra's reply to the history
        ├─ 5. Save conversation.json again
        ▼
 [Script/script.js]  gets JSON back, calls addMessage()
        ▼
 You see Lyra's reply in the chat window
```

## Why it's split into these pieces

Each file has exactly one job. This isn't arbitrary — it's what makes the
project editable without breaking things:

| Piece | Job | Why separate |
|---|---|---|
| `templates/index.html` | The page structure | Never changes once built |
| `Script/script.js` | Talks to the server, updates the DOM | Frontend logic only — no AI logic here at all |
| `Styles/styles.css` | Look and feel | Change the whole vibe without touching logic |
| `app.py` | The server — routes, memory, orchestration | The "brain stem" — wires everything else together |
| `persona.py` | WHO Lyra is | Personal, private, changes often as you tune tone |
| `tools.py` | WHAT Lyra can do | Grows over time as you add abilities |
| `conversation.json` | WHAT Lyra remembers | Just data, not code — safe to delete to reset |

The key idea: **the frontend never talks to Gemini directly.** It only ever
talks to your own Flask server. Your server is the only thing that holds the
API key and decides what to send the model. This is the standard pattern for
any AI app with a browser frontend — the key must never reach the browser.

## The three inputs that shape every single reply

Every time `/chat` calls Gemini, three things get combined:

1. **`SYSTEM_PROMPT`** (from `persona.py`) — who Lyra is, stated once
2. **`conversation.json`** — everything said so far, so she has memory
3. **`LYRA_TOOLS`** (from `tools.py`) — abilities she can reach for

Understanding this triangle is really the whole project. Everything you add
later (RAG, more tools, longer memory, voice) is just enriching one of these
three inputs.
